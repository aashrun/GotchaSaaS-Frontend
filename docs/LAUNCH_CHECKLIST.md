# Gotcha SaaS launch and dependency checklist

Based on the current implementation and configuration. Deployment and GitHub account setup remain operator-owned. OpenRouter, E2B/template and Resend are already configured locally; their credentials do not need to be supplied again. The main app currently runs locally on 7011/7012. A passing local build is not a production release.

## Remaining engineering work

- General build reliability: the four-app Luna diagnostic ultimately completed three apps after repairs/retries. The notes app passed backend checks but exhausted the call budget before UI/browser completion. Reduce redundant discovery/reads, improve evidence-driven planning and measure the repaired runtime on more held-out tasks. Do not certify arbitrary apps from this sample.
- Production generated full-stack hosting: persistent app runtimes/databases, secure app-specific credentials, migrations, preview-to-production transfer, data retention and upgrades are not provided by the static Cloudflare adapter. Exported full-stack source can be deployed with operator-managed infrastructure, but that does not establish an automated hosting feature.
- Optional Neon/Supabase provisioning: adapters exist, but runtime binding, restricted roles or RLS, health waiting, migrations, generated-app integration and deletion/reconciliation need implementation and live testing. Provide those credentials only if that feature is chosen. They are not mandatory for a static app or the existing isolated E2B preview.
- Multi-worker/production operations: exercise fencing, safe resume, ambiguous provider outcomes, quotas, failure recovery and load on deployed infrastructure. No unrestricted paid retries.
- Security and quality acceptance: broader tenant/auth/CSRF/SSRF/upload/rate-limit tests, generated-app vulnerability review, browser/accessibility compatibility and performance. Generic archives/binaries remain disabled; enabling them requires actual quarantine/scanning/content handling, not only a signature check.
- Customer connectors: Google Drive, Slack, email and similar OAuth/action adapters are planned. Define scopes, consent, encrypted credentials, approval, revocation and audit before adding them.
- Routing evaluation: compare allowed Luna/Sol/Sonnet/Opus roles using measured pass rate, repairs, cost and latency. Jev is not active. Evaluate it in shadow mode against held-out cases before changing live routes; it must not control permissions, funding or publication approval.
- Commercial reconciliation and admin UX: complete infrastructure unknown-outcome reconciliation, full provider invoice accounting, resource metrics, commercial plan catalog and any selected refund/top-up flows.

## Optional, not required for current local features

Auth0/social login (local email/password works); direct OpenAI/Anthropic/Gemini credentials (current agent uses OpenRouter); Jev routing; arbitrary packages/frameworks/Three.js beyond the curated runtime; generic binary uploads; customer OAuth connectors; custom domains per generated app. Choose and budget these separately instead of collecting every provider key.

See [deployment](DEPLOYMENT.md), [integrations](INTEGRATIONS.md), [security](SECURITY.md), [routing](MODEL_ROUTING.md) and [verification status](IMPLEMENTATION_STATUS.md). Provide secrets through the backend environment or encrypted connection UI, not a committed file.
