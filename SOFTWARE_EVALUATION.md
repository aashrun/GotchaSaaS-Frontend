# Gotcha SaaS four-application diagnostic

This evaluation uses real OpenRouter GPT-6 Luna and private E2B sandboxes through the normal authenticated job APIs, with synthetic accounts in `nebula_agent_live_test`. Provider credits are real; customer records in the operator's development database are not modified. Each job keeps the standard call/context/compute limits and reserves at most 120 ledger credits. Deployment and GitHub are intentionally outside this run, as requested.

The cases are a personal calculator (signed arithmetic and division by zero), secure browser password generator (length, character classes and symbol option), session task board (add/complete/reopen/delete), and supported Express/PostgreSQL private notes starter (authentication, persistence and cross-user isolation). Application implementation is generated by the builder, not pasted in by the operator. Static exports are independently exercised in Chrome, with mobile overflow and script errors checked. Full-stack checks run only inside the cloud sandbox.

Initial attempts revealed unnecessary intake questions despite explicit scope and repeated guessed browser control names consuming the step budget. Browser tools now accept stable `testid:` targets and dropdown selection, with instructions to use actual accessibility observations and glyph-free control names. Failed source remains unapplied and safe candidates can be reused with fresh validation. The diagnostic runner answers only questions belonging to the current job; cancelled earlier questions must not be answered or resumed. An early runner error and premature cleanup of a paused fixture were test-orchestration mistakes, separately recorded rather than counted as model failures.

The detailed attempts, costs, final functional outcomes, exported source and screenshots are retained under ignored `.local/deliverables/software-suite/`. Results establish only recorded behaviour and supported scope. A session-only board is not persistent multi-user software; a password generator is not independently certified cryptographic software; a sandbox notes database is not a durable deployed database. No result is a production security certification. Broader reliability, input-edge coverage, accessibility, browser compatibility and security review remain necessary.

See [model selection and Jev assessment](MODEL_ROUTING.md). Jev remains an evaluated proposal, not a live routing dependency. The routing change enforces GPT for ordinary web frontend work, plan-bound backend/architecture models and a separate allowance for Claude on 3D tasks. Main development servers remain on 7011/7012.

## Final outcomes

| Application         | Result                               | Independent coverage                                                                                                                           |
| ------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Calculator          | Completed                            | 12 + 8 = 20, division-by-zero error, -4 × 3 = -12, no script errors, mobile overflow                                                           |
| Password generator  | Completed after retries/tool repairs | 16/64 character lengths, upper/lowercase/digit/symbol classes, symbols disabled, different outputs, no script errors, mobile overflow          |
| Session task board  | Completed                            | Add, complete, reopen and delete; accurate counters; no script errors; mobile overflow                                                         |
| Authenticated notes | Failed complete build                | Protected TypeScript/build/backend authentication, persistence and isolation checks passed; UI/browser completion exhausted the 12-call budget |

Three of four ultimately completed, not three of four first attempts. Unnecessary questions and repeated browser labels consumed calls; the final calculator/password attempts each completed in six calls, task board in eight. The notes job's verified backend candidate remained unapplied because complete build evidence was missing. Missing browser evidence was not waived. This is a diagnostic sample from one inexpensive model, not a production certification or a comparison across all candidate models.
